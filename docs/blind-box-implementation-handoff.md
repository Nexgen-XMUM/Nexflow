## 已采用规则

- 成本加成30%加50 sen包装费；售价不超过原价70%，不满足则拒绝候选。
- 2～4件、至少1件主食、同商品跨批次最多2件。300候选/20000搜索节点上限，返回截断标记。
- U/I/D/F权重35/25/25/15；4小时紧迫窗口、库存相对值、2品类目标、偏好100/50/0。Top5 softmax，T=5/10。
- 隐藏概率 min(20%,5%+20%×毛利率+10%×饮料合格库存比例)。10积分核销后发放；100积分抵RM1，正价消费最高抵30%。
- 每模拟用户每天2盒；滚动30天两次爽约冻结7天，解冻后重新累计。只按模拟user_id，不声称手机/设备识别。
- 门店UTC+08:00，21:30开售；21:30～22:00、22:00～22:30预约，结束时刻不可再领取。
- 下单模拟付款并一次预留；未领维持库存占用并转公益；交接/报废才扣减，不释放成可售库存。
- SQLite独立盲盒演示库存，不同步旧JSON，不修改或冒充共享实物库存。

## 数据模型与接口

Product 字段为 id、name、aliases、retail_price、cost_price、weight_kg、co2e_per_kg、on_hand。Inventory 包含 MYR 币种、碳单位和商品列表。当前没有门店、批次、主食标记、品类、安全核验、过敏原、饮食核验、可售期限、预留数量或预约时段字段。

| 方法和路径 | 请求 | 响应 |
|---|---|---|
| GET /api/products | 无请求体 | products 数组：id、name、aliases、on_hand |
| GET /api/inventory | 无请求体 | currency、products：id、name、retail_price、on_hand |
| POST /api/generate-promo | 非空数组，例如 `[{"item":"croissant","qty":10}]` | currency、discount_rate、items、totals、carbon、promo、warnings |
| GET /app | 无请求体 | frontend/indexnew.html |
| GET /docs、/openapi.json | 无请求体 | FastAPI 接口文档和规范 |

促销金额是两位小数字符串，碳估算是十进制字符串。数量必须是正整数；未知商品、重复商品、超库存等返回 422；库存损坏返回 503。错误主体为 `{"error":{"code":"...","message":"...","details":[]}}`。生成接口包含成本数据，仅适合受控演示。

前端通过同源 `API = ''` 请求 `/api/products` 和 `/api/generate-promo`，使用后端金额、碳估算与文案。审批、广播、日志、回复是页面内模拟，刷新重置。没有盲盒页面和盲盒 API 对接。

## 文档冲突与架构风险

1. 最终 Word 要求成本加成定价，旧盲盒讨论稿采用 RM5/10/15 固定档位。最终 Word 优先，但 X% 和费用未确定。现有促销接口固定五折属于已有功能，不能直接替换它。
2. 最终 Word 要求下单锁库存、未领转公益池；旧稿为上架预留、超时释放。需要以最终业务流程建立新状态机，不能照搬旧稿释放库存。
3. 最终 Word 新增至少一件主食，当前数据没有主食或品类字段。不得凭商品名字补成已核验的安全数据。
4. 最终 Word 的隐藏款积分概率没有公式；评分四维只有权重，没有子项的归一化细节。旧稿可作建议，但不能当作最终批准。
5. Word 的“CO₂e Saved”与当前代码“非认证碳足迹估算”口径不同。建议区分已核销、实际交接捐赠、未领和报废，用 estimated_co2e 明确估算，不把生成方案算成已减排成果。
6. “售价减打包成本”是忽略已发生商品成本的贡献口径；它不等于商品毛利或净利润。应分别命名收入、商品成本、费用和贡献收益，确认未领订单是否计入收入，以及捐赠费用如何计入。
7. 根 README 称前端联调未完成，但页面已连接商品和促销 API。backend README 称商品选项路由仅由 demo.py 增加，也不符合当前 main.py 已提供 /api/products 的事实；其阶段计划链接在当前文件清单中缺失。
8. 前端 AbortSignal.timeout 为 15 秒，后端 AI 总超时默认也是 15 秒；可能前端先放弃响应，无法展示后端回退文案。属于需与前端队友确认的改动，本轮未改。
9. 全局 invalid_request 文案仅适用于商品数组。挂载盲盒对象请求时需要新增适配，不能让新接口返回误导提示。
10. 未认证的用户/手机号/设备字段可伪造，不能将模拟限购宣传为真正防刷。生产认证与手机号验证不在现有项目中。
11. 数据库和 JSON 若同时维护同一实物库存，会出现库存不一致。需确认迁移共用库存还是独立盲盒演示数据，不能直接复制后称为实时共享库存。
12. 300 个候选是保留上限，不是搜索复杂度上限。需限制搜索节点、返回截断标记；同商品跨批次合计限 2 件，所有预留及状态转换要事务化、幂等并重新检查可售状态。
