# 新人启动说明（当前阶段）

本包是本地比赛演示版。正式入口只有 `/app`；打烊盘点、经营看板、盲盒计算、顾客入口和打烊去向都在同一工作台。购买和积分接口暂未交付，顾客入口会明确显示待接入。

## Windows 首次启动

先安装 Python（本轮使用已有 Python 3.14 环境验证；依赖版本见 requirements.txt）。解压源代码包，在含 requirements.txt 的目录打开 PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 -m backend.desktop_demo
```

打开 <http://127.0.0.1:8000/app>。运行此命令不需要 DeepSeek Key，强制使用 local_demo，不读取付费模型作为文案来源；无需 Node 或前端构建。

已有 .venv 时直接运行第三条。启动后保持终端开启，Ctrl+C 关闭。每次重新启动都会生成一份空的临时 SQLite 数据库；正常关闭后删除，不会重置原有 data/local 数据。

## 比赛演示模式

`backend.desktop_demo` 只在本机 127.0.0.1 上运行，应用时钟固定从当天门店 21:35 开始，与电脑实际时间独立。页面顶部会明确显示演示时钟。

1. 盘点页输入 10 个 Butter Croissant，提交后在老板看板查看预计 RM30.00、毛利 RM10.00、CO₂e 估算 2 kg。
2. 切老板可复制促销文案并模拟广播。模拟广播不记收入、不加积分。
3. 以店员或老板点击顶部“登记本次盘点为演示批次”。同样的10个牛角包进入临时批次库，页面自动进入打烊去向。无需再点“载入今晚演示库存”。
4. 点击“计算去向”看候选；避开过敏原填 wheat 后重算，可看演示捐赠建议。
5. 点击顶部“推进至打烊并清算”，应用时间变为 22:31，余货进入待交接单。
6. 点击某张“确认交接”，填写演示接收机构，勾选确认后提交。回老板看板核对数量、环保估算，复制成果文字。

重新演示从 Ctrl+C 后重启开始，并刷新浏览器页面以读取新会话时钟。页面“重置草稿”只清页面草稿，不清后端库存、订单或捐赠记录。推进打烊后不能在本次进程中倒退时钟。

比赛模式已提供显式登记路径：把本次成功盘点的商品与数量登记为合成演示批次，后续建议、清算和交接都使用这一批次。安全、分类和过敏原来自三个已知商品的预设演示档案，不是实际食品安全核验；原商品目录不修改。每次服务会话只登记一份盘点；重复相同请求不重复入库，换数量或先载入独立样本后再登记会提示重启。普通服务的生产库存同步仍不在本轮实现范围。

## 使用真实时间的日常本地服务

```powershell
$env:AI_PROVIDER = 'local_demo'
$env:DEEPSEEK_API_KEY = ''
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

此命令采用现有后端的真实门店时钟和默认本地数据库，不提供演示时钟接口。需要隔离原有数据库时，为当前进程设置 BLIND_BOX_DB_PATH 指向新的演示路径。
只有用户明确要使用 DeepSeek 时才按 backend/README.md 设置服务端 .env。不要把密钥写进网页或发送给队友。

## 检查和常见问题

- 不要双击 HTML；页面要通过后端 `/app` 打开。
- 若提示端口 8000 占用，先确认是不是已有本项目服务，关闭旧服务后再启动；不要在不明状态下关闭其他进程。
- 新数据库无盲盒是正常现象。完整捐赠演示优先登记本次盘点；独立的36件样本只用于单独查看计算器，两种样本不混用。
- 非比赛模式下，下单/取餐和清算受真实门店时间限制；不要改机器时间绕过。
- 剪贴板自动复制被浏览器拒绝时，页面选择文本供 Ctrl+C 手动复制。
- 字体网络不可用时使用系统字体；Python 依赖要提前安装。后端文案、统计和捐赠演示可本地运行。
- 自动检查需要 Node.js，运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest backend/tests -q -p no:cacheprovider
node --test frontend/tests/*.test.cjs
```

本轮自动测试通过不等于队友电脑已经验证。队友首次运行后，按 [演示脚本](demo-script.md) 走一遍并在 [验收记录](acceptance.md) 的跨电脑项目填写结果。
