## 本次发现并修复

1. 原演示盘点与救援使用不同样本，没有打通同一份余货。这不是只能等待购买模块才能解决的问题。本次在比赛专用启动器新增POST /api/demo/leftovers，登记本次成功盘点的商品和数量为临时合成批次；沿用已有清算与交接接口，不修改盲盒算法或原商品目录。
2. 审批后复制失败没有可供手动选择的文案。已保留可见的已审批文本框，失败时可选中Ctrl+C。
3. 将预测区未取得的指标也统一为“暂无数据”。

登记边界：只支持当前三个已知演示商品，安全、分类、过敏原和饮食信息来自明确的合成档案，不是实际食品核验。重复相同盘点不重复入库；不同盘点或已载入独立样本时拒绝混入，提示重启会话；普通backend.main应用没有该演示登记接口。
生产库存同步、真实食品安全验证和完整登录权限没有作为新目标实现。
