# 三分钟比赛演示脚本

当前可用路线：盘点 → 老板审核和复制促销 → 盲盒/余料建议 → 模拟捐赠交接 → 经营成果。购买和取餐网页模块暂未交付，以下稿件不把它演成已完成。

## 开场前

运行 `python -X utf8 -m backend.desktop_demo`，打开 /app。确认顶部演示时钟是 21:35，三个角色按钮可用，不要预先载入独立样本；盘点后登记这份余货。每次排练重启服务用一份空临时数据库。

| 时间 | 操作 | 建议讲稿 / 预期证据 |
|---|---|---|
| 0:00–0:35 | 选店员，填 10 个 Butter Croissant，提交盘点 | “打烊余货难以及时处理。店员只填数量，后端返回价格和文案。”预测清仓 RM30、毛利 RM10、CO₂e 估算 2 kg。 |
| 0:35–1:00 | 切老板，复制 WhatsApp 文案，再模拟批准 | “老板审核后可人工复制推广；这里播放的是 WhatsApp 模拟。”收入仍为 0，广播不加积分。 |
| 1:00–1:20 | 切顾客查看入口，然后进入打烊去向 | “购买与取餐模块正在接入；积分会以同一购买账户接口为准。”当前余额显示暂无数据，不展示虚构成交。 |
| 1:20–1:50 | 切店员，点击顶部登记本次盘点；计算一次；避开 wheat 后再算 | “这是刚才录入的10件余货，登记为合成演示批次后供后端计算。安全资料是演示档案。机构是占位资料，推荐不算已交接。” |
| 1:50–2:25 | 顶部推进到打烊；打开某张待交接单，核对、勾选、确认 | “只有确认交接后，后端才扣库存并计入捐赠成果。这个操作记录是模拟交接。”可预填 DEMO charity。 |
| 2:25–3:00 | 切老板看板，复制成果文字 | “预测、模拟付款和完成取餐分开统计。当前已交接数量变化，收入不会因捐赠变成销售。环保数据是估算。”使用10件牛角包登记并全数交接时应为10件、CO₂e估算2kg、收入RM0；以屏幕数据为准。 |

## 购买负责人交付后的替换位置

把 1:00–1:20 扩为顾客模拟付款和店员取餐，并压缩前后讲解。接入后必须检查：付款只增加模拟收入；取餐才增加完成件数并结算对应积分；捐赠清单不重复计入已经领取的食品。
这部分要实走并更新 acceptance.md，才能使用“从录入到购买取餐全流程已验收”的说法。

## 备用方案

模型或网络不可用时继续使用本地模板；不会阻止演示。浏览器剪贴板受限时选中文本 Ctrl+C。准备一段本机录屏和关键截图作为现场故障备份；本轮没有制作录屏，不把截图当录屏。
