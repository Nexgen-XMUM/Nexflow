# 新页面与盲盒最小联调计划

日期：2026-10-22。基线：dev-qbc / 026567ddb6f0ed9e882387bb1f4e46c5bc5cc927。
开工检查：工作区干净，无适用 AGENTS.md。本轮所有修改留在当前分支，不提交、推送或创建 PR。

## 1. 需求

- R-1 正式页面保留清仓能力：整合新页面设计，保留计算、文案、校验、失败恢复和来源标注。来源：用户本轮要求。
- R-2 盲盒候选与余料展示：连接独立库存和计算接口，显示名称、RM 价格、拒绝原因及后端分流建议。来源：用户本轮要求。
- R-3 演示边界和积分冲突：区分两份库存、两套积分及估算，不接真实支付或发送。来源：用户本轮要求。
- R-4 可复现验收：覆盖正式页面功能、更新启动说明，保护 Key，验证不调用收费模型或修改机器时间。来源：用户本轮要求。

## 2. 逐项做法

### R-1 正式页面保留清仓能力

- 做法：以新页面样式和消费者入口整合正式入口，沿用已验证的清仓业务脚本。
- 涉及：正式页面、页面入口测试、现有前端回归测试。
- 测试入口：现有页面脚本测试、后端页面路由、桌面浏览器。
- 验收：10 个牛角包仍显示原价60、成本20、清仓30、毛利10、CO₂e 2 kg，错误可恢复。
- 难点：新页面含前端金额/碳排兜底计算和未接接口的静态促销，不能回退已修复行为。

### R-2 盲盒候选与余料展示

- 做法：独立页面区域读取盲盒库存并只读计算；按批次对应名称，sen 仅做 RM 展示转换。
- 涉及：前端卡片、盲盒库存及计算接口调用、相关测试。
- 测试入口：真实接口响应驱动页面脚本，浏览器连接临时独立数据库。
- 验收：有方案、无方案、空库存、请求失败各自清晰；捐赠机构标示演示，能源和碳排标示估算。
- 难点：批次 ID 与旧商品 ID 不同；无方案原因包括逐批次拒绝和组合规则失败。

### R-3 演示边界和积分冲突

- 做法：保留消费者样例并明确独立；后端盲盒计算不加分、不兑换、不扣库存；列出待决策规则。
- 涉及：页面提示、消费者卡片、交付说明。
- 测试入口：页面渲染和请求记录。
- 验收：页面不调用订单、支付、积分兑换或真实发送接口；前端样例积分不写入盲盒账户。
- 难点：前端按 CO₂e 样例加分，后端按隐藏款核销奖励，两者不能被解释为统一规则。

### R-4 可复现验收

- 做法：本地模板和临时盲盒数据库隔离验证，沿用现有测试工具，无新增依赖。
- 涉及：测试、启动说明和本轮汇报。
- 测试入口：全量后端与前端测试、桌面浏览器。
- 验收：测试通过；共享数据和 Key 不变；临时服务关闭；机器时间不变。
- 难点：盲盒服务存在定时清算，应使用临时数据库，不能拿共享本地库存做验收。

## 3. 实施顺序

### 阶段 1：正式页面能展示两条独立流程

覆盖：R-1 正式页面保留清仓能力、R-2 盲盒候选与余料展示、R-3 演示边界和积分冲突、R-4 可复现验收。

目标：从正式入口完成清仓生成与盲盒计算，并能看懂失败和无方案结果。

1. 整合新页面样式与消费者入口，先通过旧清仓回归测试。
2. 连接独立盲盒库存与计算，展示候选和后端分流建议。
3. 补充空库存、失败、重复请求及积分隔离测试。
4. 运行全量测试和桌面浏览器验收，更新启动说明与规则待决策表。

证明：真实接口驱动的测试与浏览器结果，金额单位核对、数据哈希和最终差异检查。
不包含：真实支付、WhatsApp 发送、订单/核销接线、积分政策统一、手机 App、修改机器时间。
