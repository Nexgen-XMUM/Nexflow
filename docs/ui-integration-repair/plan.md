## 1. 需求

- R-1 页面与数据正确：恢复现有页面入口，按实际接口展示，来源为用户修复目标 1–3。
- R-2 输入与请求可靠：严格校验数量，失败清除旧结果，处理重复与异步交互，来源为目标 4。
- R-3 来源与边界清楚：区分文案来源，保留亏损与碳估算说明，标注模拟流程，来源为目标 5。
- R-4 验证可复现：测试、浏览器、启动说明及临时服务清理，来源为用户验证要求。

## 2. 逐项做法

### R-1 页面与数据正确

- 做法：修正单一入口；录入继续使用商品选项接口，结果直接读取生成响应。
- 涉及：后端页面路由、前端渲染、现有接口测试；不扩充商品查询响应。
- 测试入口：FastAPI TestClient、现有页面脚本测试与浏览器。
- 验收：页面 200；10 牛角包显示原价60、成本20、清仓30、毛利10、CO₂e 2；没有 undefined/NaN。
- 难点：新版页面复用了旧业务脚本，需保留主题、侧栏、导览和手机样式。

### R-2 输入与请求可靠

- 做法：沿用状态和事件结构，严格解析；处理中锁定写操作，清除失效结果，允许导航。
- 涉及：前端录入、请求、重置、模拟广播；不修改库存和业务算法。
- 测试入口：现有页面脚本函数与事件、浏览器真实操作。
- 验收：小数、负数、未知/重复商品、超库存明确失败；失败可重试；旧结果和异步响应不误覆盖。
- 难点：请求过程中切换页面、旧草稿与动画状态需要一致。

### R-3 来源与边界清楚

- 做法：显示后端文案和来源；模拟操作只改变本页状态，不累计实际营收或减排。
- 涉及：草稿、KPI、日志、模拟手机和导览文字。
- 测试入口：页面脚本渲染和浏览器流程；AI 三种来源用模拟响应覆盖。
- 验收：三种文案来源可区分；亏损警告可见；广播不泄露成本且标注模拟。
- 难点：静态说明与导览也存在旧表述。

### R-4 验证可复现

- 做法：更新现有测试，使用进程环境强制 local_demo，记录浏览器验收和启动命令。
- 涉及：现有前后端测试、启动说明及本阶段汇报。
- 测试入口：现有测试命令与本机浏览器；不引入依赖或测试框架。
- 验收：前后端测试全通过；浏览器单品、多品、错误、断网重试通过；服务关闭且受保护文件无改动。
- 难点：本地配置可能启用真实模型，必须用环境变量覆盖且禁止真实上游 HTTP。

### 阶段 1：新版 UI 完整演示恢复

覆盖：R-1 页面与数据正确、R-2 输入与请求可靠、R-3 来源与边界清楚、R-4 验证可复现。
目标：用户从 /app 加载真实商品并生成正确结果，错误可恢复，模拟行为不冒充业务事实。

1. 恢复页面入口及真实字段展示，打通单品链路（任务 01）。
2. 修复输入与请求状态、文案来源和模拟边界（任务 02）。
