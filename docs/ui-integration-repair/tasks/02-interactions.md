# 任务 02：输入、请求和模拟边界

## 1. 所在位置

阶段 1 新版 UI 完整演示恢复：失败可恢复且不误导。
推进 R-2 输入与请求可靠、R-3 来源与边界清楚；前置任务 01，后续任务 03。
仅修现有前端交互和标注，不扩展服务端业务。

## 2. 开发所需

- 先读：frontend/index.html — 请求、重置、角色、导览如何共享状态？
- 先读：frontend/tests/input.test.cjs — 已有数量、文案字段测试是什么？
- 先读：backend/main.py — 错误及 promo 字段如何表达来源和回退？
- 已定：使用后端数值，三种文案来源模拟覆盖，真实调用全部 local_demo（用户要求）。
- 边界与测试入口：页面脚本函数/事件和浏览器；保留主题、侧栏和模拟手机。
- 运行：`node --test frontend/tests/*.test.cjs`；vm.Script 同时检查脚本语法。
- 未知：动态 DOM 和异步导航的交互；复用已有结构，不引入框架。

## 3. 工作流

1. 读第 2 部分，确认本任务修复状态一致性和模拟表述。
2. 让数量、失败后旧结果、三种文案来源测试先失败。
3. 严格解析输入，错误保持原输入并给出提示。
4. 修复忙碌、重置、导航和请求结束后的状态。
5. 恢复来源、亏损、碳估算及模拟标注，验证广播仅使用文案。
6. 运行对应测试，保留未提交改动。

## 4. 测试案例

| 案例 | 输入 | 预期 | 入口 |
|---|---|---|---|
| 非法数量 | 1.5、-1、未知/重复商品 | 报错，不改写数量或发请求 | 页面事件 |
| 请求失败 | 成功后422/503/断网 | 清旧草稿和金额，恢复按钮 | 请求流程 |
| 请求期间 | 重复提交/重置/切页 | 单次请求，重置禁用，不抢回页面 | 请求流程 |
| 来源 | 本地、DeepSeek、回退 | 各自清楚显示，使用 promo.text | 渲染 |
| 模拟批准 | 老板编辑后批准 | 只展示最终文案，不累计实际收入 | 页面流程 |
